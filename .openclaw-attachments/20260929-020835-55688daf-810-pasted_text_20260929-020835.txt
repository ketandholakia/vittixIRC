I've completed a full review — core protocol layer, state management, storage, security, and a UI sweep, plus `flutter analyze` (clean: 0 errors/warnings, only 14 info-level lints). Here's the analysis of **vittixIRC** (75 Dart files, ~14k lines).

## Overall verdict

This is a well-structured, thoughtfully engineered app that's clearly past the prototype stage: real connection resilience, secure credential storage, SQLite-backed paginated history, and clean layering that matches what the README claims. The main risks are in **protocol correctness** (fragile substring parsing), **UI rebuild performance**, and a **near-total absence of tests** for logic that is very testable.

## Architecture (as built)

- `core/` — raw TCP/TLS socket with heartbeat + exponential-backoff reconnect, hand-rolled IRC line parser
- `state/` — `SessionManager` singleton maps serverId → `IrcSessionController` (a `ChangeNotifier`); controllers own per-server state and route every protocol line
- `services/` — SQLite messages, secure password storage, encrypted backups, notifications, friend presence via `ISON`
- UI — constructor-injected controllers with manual `addListener`/`setState` (no Provider/Riverpod)

The layering is genuinely decoupled — the README's promise that "UI remains strictly a presentation layer" mostly holds, though a few build paths reach into `SessionManager.instance` directly (server_list_screen.dart:59,187).

## What's done well

- **Connection resilience**: 45s heartbeat with 3-minute stale detection, stepped backoff (2→60s), manual-disconnect guard, lifecycle-aware reconnect, SASL PLAIN, nick-collision retries (irc_socket_service.dart:336-368)
- **Credential hygiene**: passwords go to `flutter_secure_storage`, `ServerConfig.toJson()` excludes the password field (server_storage_service.dart:61-66, server_config.dart:79-95)
- **Storage design**: indexed SQLite schema, keyset pagination by offset-from-end, history cleanup service, merge-dedupe on reload (app_database.dart:43-44)
- **Nice touches**: system-message burst merging ("a, b and 2 others joined"), wildcard block masks, friend presence polling, notification deep-linking
- Code passes analysis cleanly and disposal hygiene in the UI is mostly correct.

## Key issues

**1. Substring matching for numerics causes false positives.** `IrcParser` detects replies with `line.contains(' 433 ')` etc. If any user's *message text* contains " 433 " or " 001 ", it's misclassified as a server error notice ("Nickname is already in use") and injected into your active chat (irc_parser.dart:503, irc_session_controller.dart:1314-1324). Numerics should be parsed positionally: split the line and check `parts[1] == '433'`.

**2. The channel user list never shrinks.** NAMES replies are merged into `usersByChannel` (irc_session_controller.dart:1417-1424), but PART/QUIT/KICK only produce system messages — nobody is ever removed. The list only self-heals because `selectTarget` clears and re-requests. While you sit in a channel it goes stale.

**3. Full traffic logging leaks credentials.** `debugPrint('IRC < $line')` (irc_socket_service.dart:119,254) logs every line — SASL base64 credentials, `PRIVMSG NickServ :IDENTIFY <password>`, and `JOIN #chan <key>`. Gate this behind `kDebugMode` and redact SASL/IDENTIFY lines.

**4. No CRLF sanitization on outgoing messages.** `sendRaw('PRIVMSG $target :$text')` (irc_session_controller.dart:691) — pasted multi-line text containing `\n`/`\r` would inject raw protocol lines into the socket. Strip control characters before writing.

**5. Network I/O inside widget build.** `chat_bubble.dart:116` creates `FutureBuilder(future: _isImageUrl(url))` inline, which performs an HTTP fetch **on every rebuild** of every bubble containing a URL. Cache the result keyed by URL (or resolve once in the model layer).

**6. Rebuild storm architecture.** Every message triggers a controller `notifyListeners()`, which both screens answer with a blanket `setState((){})` (chat_screen.dart:91, chat_shell_screen.dart:62), plus per-scroll-tick `setState` for the scroll-to-bottom FAB (chat_screen.dart:347), plus per-row entrance animations that replay on each rebuild (chat_screen.dart:1744). Fine at low traffic; janky in an active channel. Also `_sortedServers()` is re-sorted N+1 times per build (server_list_screen.dart:462).

**7. Backup KDF is weak.** `BackupCrypto` uses 10k iterations of plain iterated SHA-256 (backup_crypto.dart:70-78). Use PBKDF2 (available via `pointycastle`/`encrypt`) with ≥100k iterations, or Argon2. Backups with passwords enabled are your highest-value encrypted blob.

**8. Test coverage is one smoke test.** `IrcParser` is pure static logic — the highest-value, lowest-cost test target in the whole app — and it has zero tests, while items 1 and 2 above are exactly the kind of bug tests would have caught.

**Smaller items:** `_historyIndex` desyncs after the 101st sent message → `RangeError` in `previousHistory()` (message_input.dart:147-164 — note: the `-1` start is actually guarded, the overflow case is not); `ScaffoldMessenger.of(context)` called from `initState` crashes when shared files are pending at screen creation (chat_screen.dart:67→494); timestamps use `DateTime.now()` so no server-time; a `CAP REQ :sasl` that never gets ACKed leaves CAP negotiation hanging; dead code (`parseListReply`, `maxMessagesPerChat`, the `messages` getter in chat_screen.dart:597); `_messageKeys` GlobalKeys accumulate unbounded.

## Recommended priority

1. Anchor numeric parsing positionally + add parser unit tests (fixes #1, cheap, high value)
2. Redact/gate traffic logging (#3 — one-line security win)
3. Remove users on PART/QUIT/KICK (#2)
4. Sanitize outgoing text (#4)
5. Cache URL previews out of build (#5)
6. PBKDF2 for backups (#7)

Happy to fix any of these — items 1–4 are small, contained changes.
